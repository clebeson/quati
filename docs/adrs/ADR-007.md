# ADR-007 — Minimal DBOS waits and persistent due-time table

**Status:** Accepted for specification v8, pending implementation validation.

## Context
Quati must provide a local-first professional secretary with a modular provider ecosystem, but prior specs were too broad and tended to confuse documentation with implementation proof.

## Decision
Track due communications in Quati ledger and run bounded sweep rather than park one waiting workflow per commitment.

## Rationale
Avoid open-source long-wait memory problems and enterprise-only suspension requirement.

## Consequences and constraints
Measure concurrency after implementation; use advanced DBOS features if justified. Implementers MUST audit this decision against observed evidence before changing it; exceptions require a new ADR and affected test updates.

## Verification
In the owning slice, demonstrate one positive observable behavior, a representative failure/negative case and evidence grade. No implementation conclusion is asserted here.
