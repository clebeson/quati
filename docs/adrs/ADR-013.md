# ADR-013 — One identity and tenancy model, two deployment profiles (LOCAL and SERVER)

**Status:** Accepted (2026-11-15, owner authorization of implementation; specification v8.1). **Related:** RFC-013, ADR-014, ADR-015.

## Context
Quati must serve one person locally and many users across teams in an organization (on-premises or
cloud) with private, team and organization-wide brains. Individual local use must not need a server or
identity provider. Security must not depend on which deployment is used.

## Alternatives considered
1. **Single-user product, multi-user later as a fork or rewrite.** Cheapest now. Every data table,
   search index and cache would later need tenant and space keys retrofitted, which is a classic
   source of cross-tenant leaks. Rejected.
2. **Multi-user only (always a server).** One code path, but it blocks individuals (it needs a server,
   an IdP and a database service) and contradicts local-first. Rejected.
3. **Shared database, with each CLI connecting directly to a shared PostgreSQL.** It distributes
   database credentials to every user and moves authorization into clients. Rejected.
4. **One model, two profiles (chosen).** The same entities (tenant, principal, space, grant), the same
   AuthorizationPort and the same application layer. LOCAL runs in-process with SQLite and an OS-bound
   credential. SERVER runs `quati server` with PostgreSQL RLS and OIDC. The CLI is a thin client in
   SERVER mode.

## Decision
Option 4. The 1⇔N rule from RFC-013 §1 is normative: no "single-user" branch may skip identity,
tenant, space or authorization checks, and one conformance suite runs against both profiles.

## Consequences
- S00 already builds the identity types, token verification and AuthorizationPort, even though only
  one principal exists. This is a small cost, and it is what makes N=1 and N equivalent.
- Quati gains an HTTP API surface in S05, which needs transport authentication, rate limits and an
  API contract. "CLI-only" in PRODUCT_PRD now means "CLI is the only human UI"; the server is not a UI.
- Tenant export/import (LOCAL→SERVER) relies on globally unique ULIDs.

## Verification
IDN-10 (conformance in both profiles), IDN-02 (authorization exercised at N=1), IDN-09 (RLS).
