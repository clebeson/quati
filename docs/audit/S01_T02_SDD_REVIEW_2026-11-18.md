## Boundary (what T02 may claim)

USER_TURN only, synchronous, in-process, one read-only loop, one final M03 decision,
receipt-coordinated ephemeral publication. A01–A03 are local L2 contributions;
INT-01/INT-02 L3 stay T04. No durability, timers, follow-up revision, role fallback.
The boundary is bounded and consistent *except* where findings B2 and B3 show T02
text silently needing T03 behavior.

## Seam verification

- `Provider.complete` already calls `_reserve_call` on every loop iteration, including
  429 retries, so `_calls` already counts raw attempts; the gap is that its cap is
  `config.max_requests` (may exceed 8) while `AskSession.call` only counts logical
  calls (`len(self.model_calls) >= 8`). The contract's gap description is right in effect.
  Also confirmed: `effective.timeout_s` is fixed before the retry loop, so a retry after
  `_sleep(wait)` reuses the full original timeout, and `_sleep` is a real/injected sleep
  not tied to the AskSession clock. `reset_run` zeroes `_calls` and `_cost` only.
- `AskSession.run` today: envelope → classify → loop; social-only text is answered in
  `cli_service` via `social_outcome` before any provider call and **produces no
  RequestClassification** (finding B4).
- `ConversationSession.prepare/commit/discard` matches the contract's prepare/commit
  claim for the projection only; it has no replay, quota or work aggregate (new in T02).

## Blocking findings

**B1. M05 preflight cannot know the "chosen capability"; effect/recipient/approval
rows are unreachable before discovery (contradiction §3/§5 vs M05 §4.2).**
`RequestClassification` has no capability field (verified), yet §5 says the application
runs M05 blocking preflight *before* discovery, while ClarificationInputs
`effect_class`, `recipient_required/bound`, `approval_valid` derive from "the chosen
capability", and §5 also says only the model's actual selected invocation counts.
INT-02/A02 (external send confirmation) is therefore undefined, as is what happens
when the model selects a write after a preflight START_SAFE_WORK. §5 also says M05
once at preflight and "one final M05/M03 decision".
Fix (§5): two-phase, pure, unpublished M05 evaluation. Phase 1 (pre-discovery) evaluates
only fields knowable without a capability: target_resource, deadline, authorization_scope
(and open/asked counters). Phase 2 (after the loop, or at the first selected non-read/
required-arg-missing/refused invocation) re-evaluates with effect/recipient/approval
inputs taken from the trusted registry+M25 observation of that attempt; a selected
non-read capability **ends the loop**, no handler runs, and phase 2 yields the
confirmation ASK. M03 decides once, on the phase-2 verdict. Add oracle: model
selects send-email after one successful read → exactly one decision ASK (confirmation),
write handler calls 0, the earlier read stays in read_observations.

**B2. What happens to `safe_work`/reads on ASK_BLOCKING, WAIT, D7V, deny/escalate is
unspecified.** M03 D3 says `safe_work` = M05 parallel read work; §5 says only a model
ask without a blocking field starts reads. Fix: state that in T02 any decision other than
D8/D9 (and D5/D6 informational) performs zero discovery/reads after phase 1, and public
D3 `safe_work` is empty (parallel read work is a later-slice feature). Add to the A02
oracle: tool_calls == [] for ASK/WAIT/ESCALATE turns.

**B3. D7 / D4 / D6 / follow-up reachability is unstated; scope bleed into T03.**
Session sources include the session's own work, so M04 can return RESOLVED to a
non-terminal own work → D7 `WORK_REVISED`, which needs revision/append_context (T03,
and §1 says T02 delivers no follow-up). Likewise a user reply to an open question
hits C1/D4 forever (no answer binding until T03, M05-FR-03), and D6
(search_context, STATUS_ANSWER) needs a status read of the work store.
Fix: add a reachable-row table for T02 (D1, D2, E1, D2E, D3, D4, D5, D6?, D7V, D8, D9,
D0) and declare for each unimplemented-owner case an explicit honest outcome. Minimal:
D7 is decided purely but `apply` refuses with typed code-owned `FOLLOW_UP_NOT_IMPLEMENTED`
(BLOCKED/UNSUPPORTED, zero reads, no revision, no work claim) **before** discovery since
M04 runs first; D4 returns the QUESTION_ALREADY_OPEN WAIT with message "answer not
consumed in this build"; D6 either is declared unreachable (route → BLOCKED
uncertainty) or is limited to an explicit read of the session's own work store with a
tested oracle. Without this the "no reachable tuple selects D0" obligation cannot be
written.

**B4. Social-only turns have no RequestClassification, contradicting the required
USER_TURN classification (S01_RUNTIME_CONTRACT §5).** `social_outcome` answers with
zero provider calls. Fix: define a code-owned classification for the table match
(provenance `CODE_SOCIAL_TABLE`, never model/provider evidence, hash recorded) so D5
SOCIAL_GREETING is produced by M03 with zero model calls; or state that the social path
bypasses M03 (then M03-FR-01 oracle must say so). Also decide that a social turn counts
against the 1000-turn quota and is receipted and revision-advancing like any ask.

## Required clarifications (non-blocking but must be in the spec before tests)

**C1. Replay key reachability and receipt semantics.** S01 §5 defines the key as
`request_id`, but §4 of the S01 contract says request IDs are fresh per ask, so the public
CLI can never replay. State that replay is proven only at the application level
(`tests/integration/test_s01_interaction_apply.py`), and define what a replay does:
receipt written or not, whether the revision advances (T01: advances once per receipted
response; replay returns the *original* revision before CAS). Recommended: replay writes
its own receipt marked REPLAYED, output_hash over the returned bytes, no projection
advance, no read/model call. Oracle: replay = 0 provider/read calls, byte-equal TurnResult,
mutated returned Response does not alter the stored copy.

**C2. Quotas (1000 turns / 20 works) vs "before model/capability effects".** Whether a
turn creates work is known only after classification. Define: turn quota checked at
admission (before any model call); work quota checked after classification and phase-1,
before any capability effect. Say which decisions allocate a `work_ref` (D8/D9, D3 when
nontrivial; not D1/D2/D5/D6/D7V/E1) and whether a quota refusal is a receipted refusal that
advances the projection (recommended: yes, no turn summary, no work, no eviction).
A discarded (sink-failed) candidate must not consume quota or IDs observable by replay.
Oracles at 999→1000→1001 turns and 20→21 works. Name the limits as code constants
recorded in the receipt/trace (they are intentionally not in decision-policy).

**C3. Role staging is not mapped to an M03 row.** "BLOCKED NOT_CONFIGURED
ESCALATION_UNAVAILABLE without another model or discovery call" leaves the "exactly
one decision per event" rule (M03-FR-02) unmet. Map it to E1 (typed dependency_error
`ROLE_NOT_QUALIFIED`, after deny/escalate) → ESCALATE DEPENDENCY_UNAVAILABLE with public
status BLOCKED/NOT_CONFIGURED. Define the exact predicate for "qualified": which roles the
selected default provider may serve in T02 (recommend: only the configured default
role; every other recommendation is unqualified until MOD-01/T03). Oracle: strong-role
recommendation → model calls == 1 (classification only), discovery calls 0.

**C4. ESCALATE and uncertainty outward behavior.** D2, D2E, E1, D7V, D0 all yield
ESCALATE but S01 has no escalation channel. Add the decision-action × reason →
(Response status, result_kind, error code, work/launched/delivered fields, message
template ID) mapping table, including D5 non-table social label (reason SOCIAL_OTHER but
public BLOCKED uncertainty) and D5 DIRECT_ANSWER without trusted context. State that
no message claims a human/SME was notified. Table-driven test over every row.

**C5. Producer-failure → row mapping.** §4 says a source outage yields "assumption and
typed unavailability… one focused question/unavailability" (D3 question or E1?). Add a
table: M04 source down and required → E1; M04 source down but not needed → assumption;
registry/ACL/audit down on a read route → E1; sink down → receipt failure path;
UNRESOLVED with non-null hint → D3 target_resource. Include E1 vs D1/D2 precedence oracle
(deny + dependency_error → POLICY_DENIED).

**C6. Raw-attempt budget details.** Specify: cap is `min(8, config.max_requests)` shared
by logical calls, repairs and 429 retries; `AskSession.call` must read the provider's raw
count (new accessor) rather than its own list length; each transport attempt recomputes
`timeout_s = min(configured, remaining)` and refuses to sleep past the deadline;
`_sleep` must be the injected one and advance the injected clock in deterministic tests;
`reset_run` rebinding must not change `config_hash`/probe key (assert equality). Oracles:
three 429 retries + 5 more calls → 9th refused BUDGET_EXCEEDED before transport;
retry delay beyond remaining deadline → DEADLINE_EXCEEDED with zero further attempts;
provider max_requests=3 wins over 8.
