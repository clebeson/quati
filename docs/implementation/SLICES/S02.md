# S02 — Ledger-backed durable commitments and outcome judgment

**Status:** see `docs/implementation/implementation_state.json` (the only status authority). **Modules:** M06, M07, M09, M10, M26.

## User-visible outcome

Introduce the commitment ledger behind one LedgerPort (SQLite for LOCAL; the PostgreSQL backend passes the same conformance suite), the ledger-driven worker (ADR-015, ADR-016), timers with catch-up, outbox, evidence review and local inbox delivery; replace temporary work runner rather than running two divergent implementations.

## Required proof (not a mock-only pass)

- **S02-GATE-01:** Worker SIGKILL and restart preserves one root commitment and catches up.

- **S02-GATE-02:** Uncertain provider send does not generate duplicate effect nor false delivered state.

- **S02-GATE-03:** Time-simulated progress due event creates one meaningful communication.

- **S02-GATE-04:** Insufficient evidence becomes honest partial or bounded deeper investigation before final.

## Profile scope

For the product MVP (ROADMAP "Product MVP") the S02 gates are proven on the LOCAL profile: single user, SQLite ledger, ledger-driven worker and local inbox delivery, on Linux. Multi-user and PostgreSQL/RLS behavior is the SERVER profile and is proven in S05. IDN-03 (personal-to-organization write requires approval) is an S02 gate case.

Model-dependent gates require actual approved LLM calls and logged tool trajectories. Recovery gates require the real SQLite ledger on a local filesystem, a real worker process and real process interruption (SIGKILL); the RFC-003 conformance suite runs against every LedgerPort backend present. Live external smoke remains separately verified.

## Red-team requirement

Reproduce one adversarial case from each affected *distinct enforcement boundary*: policy, statechart, evidence, recipient or provider. Avoid copying the same test to every PRD. Independent reviewer selects one negative from the module threat sheets that the implementer did not optimize for.

## Stop condition

Do not proceed when the evidence for any required gate is `BLOCKED`, `FAIL` or only lower-tier. Do not invent security/persistence guarantees or use direct mock tool invocation to pass actual model selection.
