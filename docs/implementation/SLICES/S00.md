# S00 — Live model + capability discovery + compiler foundations

**Status:** see `docs/implementation/implementation_state.json` (the only status authority; this file records no gate status). **Modules:** M01, M02, M14, M15, M17, M25, M26, M30, M31.

## User-visible outcome

Create a working `quati ask`, and the line-based `quati chat` session that runs the same use cases one input line per turn (M01-FR-04), with one configured actual provider and two safe tool-capable fixture capabilities; compile one interaction profile and one statechart, and let a model spontaneously search/describe/invoke a capability for an unknown request.

## Required proof (not a mock-only pass)

- **S00-GATE-01:** `quati doctor` reports provider feature support and missing credentials without failure of unrelated CLI actions.

- **S00-GATE-02:** A real model consumes a natural-language request and uses on-demand SCS discovery without gold labels. CAP-01 and CAP-02 each pass in 30 of 30 repeated live runs, with logged trajectories and provider/model identity recorded; if the configured model fails, another configured model may be tried and recorded. MOD-01 (30-case sealed benchmark) is not an S00 condition; it is a precondition for enabling autonomous routing/role promotion (S04 or later).

- **Chat acceptance (deterministic, part of S00-T01 done conditions):** M01-AT-03 — a scripted transcript piped to `quati chat --jsonl` equals the one-shot `--json` command sequence and ledger state; M01-RT-03 — command-like or approval-like text from a turn, model reply, tool or document result is never dispatched. Every later capability is exercised through this terminal path; no GUI or TUI work starts before S07 passes.

- **S00-GATE-03:** A greeting causes no capability invocation; a disallowed write is rejected by the code-level policy gate.

- **S00-GATE-04:** Compiling changed behavior yields deterministic hash and invalid statechart is rejected.
